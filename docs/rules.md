## Rules
- use layered clean architecture
- All entities must inherit from `BaseEntity` for audit fields (`id`, `createdAt`, `updatedAt`, `createdBy`, `updatedBy`, `deletedAt`). This follows the DRY principle to avoid repeating audit columns across entity classes.
- Use global query filters in DbContext to auto-filter soft-deleted entities (`where DeletedAt is null`).
- Use base repository pattern to avoid rewrites common rep methods.
- Use configurations for db set rules.
- Use fluent validation for dto validations.
- Use records for dtos
- Use extension methods for each layer to add their di dependencies.
- Use light modular folder structure across all layers. Group related code by domain category (e.g. `Room/`, `Booking/`, `Staff/`, `Service/`, `Housekeeping/`). This applies to: entities, enums, repositories, services, controllers, contracts and DTOs. Each module folder should contain its own types and only reference other modules through their public surfaces (FKs, ids, service interfaces).

├── BaseEntity.cs
├── Room/Entities/ ...

- Cross-module communication: only through IDs (FKs) and service interfaces, never direct entity references across modules.
